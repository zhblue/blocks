积木 ↔ C / C++ 的对应关系与已知限制
  • 工具栏「语言」默认 C++：输出走 std::cout、读入走 std::cin，按需带 #include <iostream>，bool 是内建类型不需要头文件。切回 C 就是 printf / scanf + #include <stdio.h>，用到 true/false 时自动补 <stdbool.h>。
  • 「printf / scanf」积木在两种语言下都照 C 那套语义生成（C++ 里额外带 #include <cstdio>），格式说明符数量和类型都会校验；「读入」积木选 C++ 时不再关心 %lf 之类的坑。
  • 不管选哪种语言，生成的都是 C 风格代码：原生数组、C 风格强制转换、(类型) 括号照旧加，不会替你变成 std::string / std::vector / static_cast。
  • 「输出」积木自动推导格式符（int→%d、double→%g、char→%c）；要手写格式串就用「printf / scanf」积木，说明符数量和类型都会校验。
  • 「读入」只接受变量或数组的第 i 项（要的是能往里写东西的地方，算出来的数值不行），小数的原生格式必须写 %lf。
  • 声明就地生成，作用域与手写 C 完全一致：循环里声明的变量出了循环就不存在，越界使用时诊断会指名道姓。
  • 数组不做越界检查（和 C 一样），下标越界是未定义行为；局部数组请给出合理大小。
  • 「函数」积木会自动前置函数原型，所以递归和互相调用不受摆放顺序影响。
  • 编译器是 wasi-sdk 里的 clang 8.0.1：C 认 c89/c99/c11/c17，C++ 认 c++98/c++11/c++14/c++17/c++2a。「标准」下拉框会跟着语言换成对应的那一份；想要 C++20 就选 -std=c++2a，这个 clang 还不认识 c++20 这个名字。没有真实磁盘，文件读写只在内存 FS 里。
  • 死循环靠 worker.terminate() 掐断，超时后拿不到精确 CPU 时间；wasm 内存超限以 memory access out of bounds 报出。
