# 积木编程 → C / C++（blockly-c-playground）

拖积木写程序，一键生成等价的 C 或 C++ 代码，再在浏览器里用 clang.wasm 直接编译运行。
仿 Blockly / Scratch 的交互，但生成的是真代码：变量、数组、循环、判断、函数、递归都按 C 的规则来（先声明后使用、作用域、格式串与实参配对）。
工具栏的「语言」默认 C++（`std::cout` / `std::cin` / `#include <iostream>`），也可以切回 C（`printf` / `scanf`）—— 换的不只是编译参数，生成的源码写法本身会变。

源码仓库：<https://github.com/zhblue/blocks>（页面标题点进去就是这个地址）。

整个目录自包含：Blockly、Ace、wasm 工具链和 sysroot（416 个文件，含 libc++ 头与静态库）全部在本地，不联网、不引用目录外的任何文件，拷走就能用。

## 运行

```bash
cd blockly-c-playground
python serve.py 8010
```

然后打开 http://127.0.0.1:8010/index.html

必须走 http，不能直接双击 `index.html`：`file://` 下浏览器不允许加载 Worker，wasm 编译链路起不来。
`serve.py` 给 `assets/`、`vendor/` 打了长缓存，第二次打开基本秒就绪；首次加载约 58 MB（clang.wasm 29.8 MiB、lld.wasm 18.6 MiB、sysroot.tar 8.9 MiB、memfs.wasm 0.3 MiB）。
生产部署建议再叠一层 gzip/brotli：这类 wasm 二进制和 tar 里大量文本头文件压得动。

页面打不开或一打开就转圈（本地存档被改坏时可能出现）：访问 http://127.0.0.1:8010/index.html?fresh=1，会跳过并清掉本地积木存档。

## 界面

左：积木工作区（六个分组：控制 / 变量 / 输入输出 / 运算 / 判断 / 函数）。
右：代码面板（可以手改再点「编译并运行」，但代码不会反向变回积木）、标准输入、运行输出、诊断列表。标题本身是个链接，指向 <https://github.com/zhblue/blocks>；说明文字收在标题的悬停提示里。
代码面板标题栏右边那颗胶囊写着当前状态：**跟随积木**（改积木代码就跟着改）或 **已手改**（你在面板里敲过字，积木的改动不再覆盖这里）。点它就按当前积木重新生成，等于工具条上的「按积木重新生成」。
中间那根竖条可以拖动（也能双击、键盘调），用来改左右两栏的宽度比例。

按钮：按积木重新生成 / 编译并运行 / 停止 / 重载工具链 / 保存 / 导出 / 导入 / 清空积木。

工作区一变就重新生成代码，诊断既列在面板里，也用气泡钉在出问题的积木上。
这条「一变就生成」的链路（`js/app.js` 的 `scheduleRegen()` / `runRegen()`）有三层保护，都是冲着「代码面板不动了」这种反馈去的：
只认内容事件（点击、选中、滚视口、开气泡这类纯 UI 事件不再把防抖重新计时）；防抖 120ms 带 400ms 最长等待（拖着积木一直有事件时也能看到代码跟着走）；生成过程兜异常（抛错会把错误摆进诊断列表，并且照样存档，不会一声不响地既不更新也不保存）。
另外 Blockly 13 的变更事件是靠 `requestAnimationFrame` 派发的，页面切到后台时 rAF 被浏览器挂起、事件压在队列里不发，所以重新可见 / 重新拿到焦点时会主动补一次生成（手改过的面板不动）。
「编译并运行」把代码交给常驻的 compile.worker（clang.wasm + lld.wasm）链成 wasm，再交给一次性 run.worker 在沙箱里执行，stdin 走「标准输入」框。
选项：语言（C++ / C，默认 C++）、标准（跟着语言换候选）、优化（-O0/-O1/-O2/-O3）、运行超时、是否在代码里保留中文注释、白天/夜晚模式；编译带 `-Wall`，栈大小默认 8 MB（`js/wasmclang.js`）。
「代码里带中文注释」直接改生成出来的代码，所以勾上/去掉会立刻重生成；标准、优化、运行超时只影响编译参数，不动代码。

「语言」这一栏同时改两件事：
生成器的写法（`js/c-generator.js` 里 `opts.lang === 'cpp'`）和编译参数（`clang -cc1 -x c++` 还是 `-x c`，文件名 `main.cc` / `main.c`）。
「标准」下拉框的候选来自 `js/app.js` 里的 `LANGS`，是按这份 clang.wasm（wasi-sdk 的 **clang 8.0.1**）二进制里实际认得的语言名列的：
C 是 `c89/c99/c11/c17`，C++ 是 `c++98/c++11/c++14/c++17/c++2a` —— 这份 clang 的语言表里没有 `c++20` 这个名字（只认 `c++2a`），想要 C++20 就选 `c++2a`。

「白天模式」那个复选框只换配色，不动积木、代码和编译参数，做法是给 `<html>` 挂一个 `.day` 类：
页面里的颜色全部取自 `<style>` 顶部那一组 CSS 变量（`--bg` / `--panel` / `--fg` / `--acc` …），`html.day` 把整组变量换成浅色值，所以加新颜色时请往变量里加，别在规则里写死十六进制。
例外是代码面板：Ace 的主题是它自己的一套 CSS，白天用打包在 `vendor/ace/ace.js` 里的默认主题 `textmate`，夜晚用 `vendor/ace/theme-one_dark.js`，切换时由 `js/app.js` 的 `applyTheme()` 调 `setTheme()`。
积木画布两种模式都是浅底（Blockly 的积木颜色本来就是按浅底调的，而且它注入时会自己往 `<head>` 追加 CSS，改深色要额外打架）。
选择存在 `LS.opts` 的 `theme` 字段里，`<head>` 里那段内联脚本会在首屏绘制前先把 `.day` 挂上，免得每次打开闪一帧深色。

两个区中间那根竖条可以拖动，用来调积木区/代码区的宽度比例（按住拖、双击回默认 58%、Tab 聚焦后左右方向键每次 2%、Home 回默认）。
实现上它不改像素，只把百分比写进 `<main>` 的 CSS 变量 `--split`，`grid-template-columns: minmax(var(--pane-l-min), var(--split)) var(--bar-w) minmax(var(--pane-r-min), 1fr)` 自己分配，所以缩放浏览器窗口时比例自动跟着走。
夹限有两层：`js/app.js` 的 `SPLIT.min/max`（18%~82%，也是 `index.html` 里 `aria-valuemin/max` 的值）是不管窗口多宽都不许超过的边界，CSS 那两条像素下限（积木区 240px / 代码区 280px）在窄窗口下会先生效。
拖的时候必须按「当前窗口真正能兑现的区间」夹，否则会出现「JS 写 82%、浏览器只给 76%，条停住不跟手」，所以 `splitBounds()` 每次现量一次布局（`splitMetrics()`）把两层合成一个区间，那几个像素值只写在 CSS 里、JS 从计算样式读，不留第二份数字。
比例存进 `LS.opts` 的 `split` 字段，松手才写（拖动过程中一路改宽度，不存）。
还有一点必须手动处理：Blockly 的 SVG 尺寸是注入时算的、只监听 `window resize`，Ace 也一样，容器被我们改窄不会自愈，所以每次改完宽都要在下一帧叫一次 `Blockly.svgResize(workspace)` 和 `srcEditor.resize()`（`relayout()`，用 `requestAnimationFrame` 把一次拖动的几十个 `pointermove` 合并成一次重排）。
`test/split-probe.mjs` 就是照着这套数字断言的：把 app.js 里那一节抽进 vm 假 DOM，量「光标→百分比→条中心」跟不跟手、各窗口宽度下夹限算得对不对、存档和重排的时机对不对；改了 `index.html` 里那几个像素值它会红。

## 积木与代码的对应

下表写的是 C 模式；C++ 模式只有表后那张对照表列出的几处不同，其它生成规则完全一样。

| 积木 | 生成的 C |
| --- | --- |
| 主程序 | `int main(void) { … }`（不放它时，主工作区上散落的语句按顺序进 main） |
| 如果 / 如果…否则 | `if (…) { … } else { … }` |
| 重复 N 次 | `for (int c_i1 = 0; c_i1 < N; c_i1 += 1)` |
| 当…就重复 / 重复直到 | `while (…) { … }` / `do { … } while (!(…));` |
| 计数循环 从 a 到 b 步长 s | `for (int i = a; i <= b; i += s)`（步长为负时自动换成 `>=`） |
| 跳出 / 继续 | `break;` / `continue;`（四种循环里都能用：计数循环、重复 N 次、当…就重复、重复直到；放在循环外才报错） |
| 声明 int/double/char/bool/文本 变量 | `int x;` / `int x = …;` / `char c = 'A';` / `bool ok = true;` / 文本见下表 |
| 把…设为 | `x = …;`（C 的文本变量自动变成 `strcpy(s, …);`） |
| 变量（值块） | `x`，C 模式放进 scanf 槽位时自动变成 `&x`（文本变量是数组名，本来就是个地址，不加 `&`） |
| 声明数组 / 第 i 项 / 设为 | `int a[5];` / `a[i]` / `a[i] = …;`（元素类型没有「文本」这一档） |
| 输出…（自动换行） | `printf("…\n", …)`，格式符按内容类型写死 |
| 读入变量 / 读入整个数组 | `scanf("%d", &n)` / 循环 `scanf`；小数自动用 `%lf`，读字符自动加前导空格 `" %c"`，读文本自动带缓冲区上限 `"%255s"` |
| printf / scanf（进阶） | 自己写格式串 + 实参槽，格式符数量与实参会逐项核对 |
| 数字 / 文本 / 字符 / 真假值 | `42`、`"文本"`、`'A'`、`true` / `false` |
| 加减乘除余、取负、转类型 | `a + b`、`-a`、`(double)x`，按 C 优先级自动补括号 |
| 比较、与或非 | `==` `!=` `<` `<=` `>` `>=`、`&&` `||` `!` |

运算和判断这几块积木，**脸上写的符号就是代码里的那个符号**：`-` `*` `/` `%`、`==` `!=` `<=` `>=`、`&&` `||` `!`，
不用 Scratch 那套 `×` `÷` `≠` `≤` `≥`「且」「或」「非」。从 Scratch 过来的学生少一层翻译，
中文说法收在悬停提示里（`&&` 就是「且」，`||` 就是「或」，`!` 就是「非」）。诊断列表里的标签也跟着用同一套符号。
下拉的**值**一直是 C 的运算符（`OP` 字段存 `==`、`&&` 这些），改的只是显示文本，生成器一行没动。
| 函数（返回值类型 + 形参） | 先出原型再出定义，谁先谁后都能互相调用，递归可用 |
| 调用函数（语句 / 表达式） | `fact(5);` / `x = fact(5);`，实参槽随被调函数的形参自动增减 |
| 返回 | `return …;`（void 函数是 `return;`） |

用到的头文件由生成器按需插入：C 模式是 `<stdio.h>`，出现 `true/false/bool` 时补 `<stdbool.h>`，
文本变量赋值用到 `strcpy` 时补 `<string.h>`。

切到 C++ 后只有这几处写法不同，其余（循环、判断、数组、函数、类型、优先级补括号）与 C 一模一样：

| 积木 | C 模式 | C++ 模式 |
| --- | --- | --- |
| 输出… | `printf("…\n", x)` | `std::cout << x << std::endl;`（没勾换行就是 `std::cout << x;`） |
| 读入变量 / 数组第 i 项 | `scanf("%d", &n)` / `scanf("%lf", &a[i])` | `std::cin >> n;` / `std::cin >> a[i];`，没有格式符也没有 `&` |
| 读入前的 flush | 补 `fflush(stdout);` | `std::endl` 本身就 flush；只有上一条输出没勾换行时才补 `std::cout << std::flush;` |
| 主程序 / 空参函数 | `int main(void)`、`void shout(void)` | `int main()`、`void shout()` |
| bool | 需要 `#include <stdbool.h>` | 内建类型，不带头文件 |
| 头文件 | `#include <stdio.h>` | 用到 cout/cin 才 `#include <iostream>` |
| printf / scanf 积木 | `printf` / `scanf` + `<stdio.h>` | 还是 `printf` / `scanf`，改成带 `#include <cstdio>`；格式串校验一字不变 |
| 输出比较式 / 与或 | `printf("%d", x > 1)` 不需要括号 | `<<` 的结合力高于 `>` 和 `&&`，所以自动写成 `std::cout << (x > 1) << std::endl;`，不加括号会被解析成 `(cout << x) > 1` |
| 声明「文本」变量 | `char s[256];` —— 一块定长字符数组，数组名就是字符串 | `std::string s;` + `#include <string>` |
| 文本赋值 / 读入 | `strcpy(s, "hi");` / `scanf("%255s", s);`（不加 `&`，宽度是硬上限） | `s = "hi";` / `std::cin >> s;` |
| `printf` 的 `%s` 配文本变量 | 直接传数组名 `s` | 自动补成 `s.c_str()`：`std::string` 是对象，不能直接进可变参数，写了就编译不过 |
| `scanf` 的 `%s` 配文本变量 | 可以，自动带宽度 | 拒绝并让你改用「读入到变量」：`%s` 要往 `char*` 里写，`std::string` 这时还没有分配内存 |
| 文本比较 / 拼接 | 一律报错（比的是地址，要用 `strcmp`，本版没有） | `s == t`、`s + t` 都按内容走，可以直接用 |
| 文本当函数参数 / 返回值 | 报错：数组传进函数只剩地址，收不到「这块缓冲区多大」 | 可以，按值传 `std::string` |

数组、`char`、强制转换在 C++ 模式下仍是 C 那一套：还是原生数组、还是 `(double)x`，不会生成 `std::vector` 或 `static_cast`；
唯一按语言变身的类型是「文本」—— 上面那几行。
诊断里的措辞也沿用「C 的标识符…」这类说法 —— 两门语言的标识符规则相同，只有 bool 读入那一条会按语言各说各的（C++ 解释 `cin` 把 0 / 非 0 当 false / true）。

## 诊断口径

生成器只在结构明显会出事时报错，并把话说清楚（下一步该拖哪块积木）：

- 错误：格式串与实参数量不符、用了没声明或声明在后面的名字、中文变量名、scanf 的写入目标类型不对、`break` 在循环外、有返回值的函数最后一条不是「返回」、调用 void 函数却想拿它的值、文本出现在说不通的地方（整块文本塞进数值槽、C 里比较文本、C++ 里用 `scanf %s` 读 `std::string`、C 的函数想收或发文本）。
- 警告：散落在「主程序」外面的语句链（会被挪到 main 末尾，导致前面的语句看不到这个声明）、数组越界提示等。
- 提示：数组长度等说明性信息。

变量名下拉的候选来自「按 C 作用域规则对这个槽位可见」的声明：同一程序体里、排在它前面。
所以「声明」拖在后面、或没接进程序体时，下拉里确实没有它 —— 这时下拉会写明原因，而不是让你以为没识别到。

## 已知限制

- 只覆盖入门编程：没有指针运算、结构体、联合、文件读写、多文件、宏、`switch`。选 C++ 也不会给你类和模板 —— 积木本身没有这些概念。
- 数组必须声明时定长，长度是常数；不支持二维数组和变长数组。
- 文本变量：C 那边固定是 `char s[256]`，最多 255 个字符（一个汉字占 3 字节），超长会在生成阶段报错；长度写死，不能按积木改。
- 没有字符串函数库：`strcmp` / `strlen` / `substr` 这类积木还没有，所以 C 里的文本只能整体读、整体写、整体打印，比不了内容。
- 读文本只读到一个词：`cin >> s` 和 `scanf("%255s", s)` 都在空格 / Tab / 换行处停下，读不进一整行。
- `char` 数组（「声明数组」选 char）能存能读，但它的每个格子是一个字符，不是一整块文本；要整块文本请用「声明变量」选文本类型。
- 代码面板是「出口」不是「入口」：手改的代码只用来编译运行，不会解析回积木；点「按积木重新生成」就被积木覆盖。
- 执行在浏览器沙箱里，栈大小和运行超时可调，但死循环只能靠超时打断；`exit()`、`assert()` 这类需要运行期的行为不保证与本地一致。
- 编译产物是 wasm32 语义，`long`、指针宽度等与 64 位 Linux 本地编译不完全相同，讲课时别拿它做数据大小的对照实验。
